# Площадки курса Б.1.2.2 (ИСТ-51)

Интерактивные площадки к дисциплине «Основы программирования систем
искусственного интеллекта на языке Python», профиль ИСТ-51. Каждая площадка
следует тематике одного из четырёх модулей лабораторных работ.

Лекция в ноутбуке показывает результат. Площадка позволяет его покрутить:
подвинуть параметр и сразу увидеть, что изменилось. **С занятием площадку
связывает тема, а не примеры:** данные, термины и числа на ней могут отличаться
от лекционных. Тесты проверяют то, что площадка утверждает, как свойства —
утечка завышает оценку, гибкая модель проигрывает на новых данных, сломанный
обратный проход ловит проверка градиента, — а не как цитаты из лекций.

Python исполняется в браузере через [stlite](https://github.com/whitphx/stlite)
(Pyodide), поэтому опубликованный сайт — статические файлы без серверной части.
Студенту не нужно устанавливать ничего.

Площадки живут в одном репозитории и на одном сайте с площадками курса
«Основы машинного обучения» (магистратура, лингвистика): общий каркас, общий
пакет `playground_common`, общий каталог по темам. Раздел курса —
<https://konkin-nikita.ru/gd_learn/ml-practice/>, каталог —
<https://konkin-nikita.ru/gd_learn/topics/>. Как собрать и развернуть сайт —
в [README](../README.md) репозитория; здесь — только то, что относится к
ИСТ-51.

Тема каталога — заголовок, под которым площадка стоит в каталоге и в строке «Тема …»

Материалы курса ссылаются на площадки: в лекциях 2, 4, 5, 6, 7 и 12 есть слайд

задаётся в одном месте — константа `URL` в файле `площадки.py` рядом с

## Конвейер подготовки данных (`data`)

| Что видно при настройках по умолчанию | Значение |
|---------------------------------------|----------|
| Пропусков / полных дубликатов в шести строках | 2 / 1 |
| Чем заполнены пропуски: медиана после удаления выбросов | **−48.65** |
| То же средним **до** удаления выбросов | **−332.43**, два невозможных значения |
| Память: список против массива | замер в браузере |

Медиана, посчитанная до удаления выбросов, ошибается тихо (−52.30), среднее —
громко: −332.43 ниже физического предела −120 дБм. Заполнение вносит в таблицу
новую ошибку вместо того, чтобы исправить старую. Вкладка «Тысяча строк»
повторяет опыт на синтетических показаниях с ручками для доли пропусков и
выбросов; «Векторизация и память» меряет генератор, NumPy и скалярное
произведение в браузере. В Pyodide указатель занимает 4 байта, поэтому список
там легче, чем в настольном 64-битном Python, — площадка об этом говорит, а не
прячет.

Чего не делает: не заполняет пропуски по группам и не интерполирует ряд; не ищет
выбросы статистически — правило одно, физический предел; не оптимизирует типы и
не читает файл частями.

## Утечка данных (`leak`)

| Что видно при настройках по умолчанию | Значение |
|---------------------------------------|----------|
| Оценка с утечкой | **0.757** |
| Честная оценка | **0.510** |
| Истина (данные — чистый шум) | 0.500 |
| Разрыв, придуманный утечкой | **+0.247** |
| Признаков с p < 0.05 из 2000 | 108 (случайность даёт около 100) |
| Выдержали поправку Бонферрони | 0 |
| Переотобраны во всех 5 блоках | 1 из 20 |

1. **Разрыв держится в каждом блоке**, а не возникает в среднем по удачному
   разбиению.
2. **Отобранные признаки не переживают смену блока.** Признак с настоящим
   сигналом переотбирается во всех блоках; здесь настоящих нет вовсе, и до
   верха дотягивается ровно один из двадцати. Поднимите «силу настоящего
   сигнала» до 0.6 — таких станет пять, и это будут именно те пять столбцов,
   в которые сигнал положен.
3. **p-значения распределены равномерно.** Левый столбец гистограммы — не
   открытие, а двадцатая часть равномерного распределения.

Ветви различаются только тем, где сделан отбор: масштабирование и модель у них
общие. Тест `test_the_branches_differ_only_in_where_they_select` держит это
свойство.

Чего не делает: не показывает другие виды утечки — признак из будущего,
дубликаты между частями, целевое кодирование; не меняет модель, потому что
утечка — свойство порядка операций, а не модели; не считает вложенную
кросс-валидацию.

## Метрика и дисбаланс (`metric`)

| Что видно при настройках по умолчанию | Значение |
|---------------------------------------|----------|
| Ответ «отказа нет» всегда: доля правильных | **97,9 %**, найдено 0 |
| То же на SECOM (базовый уровень задания на РГР) | **93,4 %**, PR-AUC **0.066** |
| Требуемая полнота 0.95 | полнота 0.94, точность 0.08, порог 0.303 |
| Самый дешёвый порог, пропуск в 10 раз дороже тревоги | **0.834**, стоимость 61 |
| Без поправок / веса классов / уменьшение большинства | полнота 0.367 / 0.333 / 0.650 |

Порог меняет только решение модели, цена — только оценку решения: это две
разные ручки. PR-AUC трёх способов борьбы с перекосом различается в третьем
знаке, а полнота при пороге 0.5 — вдвое: способы в основном сдвигают рабочую
точку на почти одной и той же кривой. Веса классов здесь полноту снизили: у
леса из полностью выращенных деревьев вероятность в чистом листе от весов не
зависит.

Чего не делает: не обучает модели в браузере; не работает с AI4I 2020 — модель
там у каждого студента своя; цена ошибки задана одним отношением.

## Сложность модели (`fit`)

| Что видно при настройках по умолчанию | Значение |
|---------------------------------------|----------|
| Ошибка на обучении, степени 1 / 4 / 17 | 0.286 / 0.059 / 0.023 |
| Степень 17 на новых точках | **13.2** против 0.575 у ответа «среднее» — в 23 раза хуже |
| k = 1 / 15 / 99: доля правильных на проверке | 0.950 / 0.957 / 0.847 |
| Дерево глубины 3 | 0.900 на обучении, 0.890 на проверке |
| Lasso при наибольшем штрафе | обнулено 10 из 10, R² −0.006 |
| Lasso при alpha ≈ 10 | обнулено 6 из 10 |

Цена переобучения при k = 1 здесь мала (0.950 против 0.957), цена
недообучения при k = 99 — велика. Ridge и Lasso при одной alpha штрафуют с
разной силой: Lasso в scikit-learn делит ошибку на удвоенный размер выборки,
Ridge — нет. Ошибка степени 17 на новых точках показана с одним знаком после
запятой: многочлен плохо обусловлен, и NumPy в браузере расходится с
настольным в четвёртой значащей цифре.

Многочлен решается своим методом наименьших квадратов (`scipy.linalg.lstsq`), а
не `LinearRegression`: с версии 1.9 scikit-learn отбрасывает малые сингулярные
числа, степень 17 перестаёт «взрываться» между точками, и переобучение, ради
которого вкладка существует, пропадает. Своё решение ведёт себя одинаково при
любой версии.

Чего не делает: не подбирает гиперпараметры автоматически; не меняет данные; не
сравнивает ансамбли — в браузере они обучаются долго, а о сложности модели
нового не говорят.

## Нейросеть на NumPy (`nn`)

| Что видно при настройках по умолчанию | Значение |
|---------------------------------------|----------|
| Потери до обучения | **0.7102**, около ln 2: необученная сеть — монетка |
| Градиент W1[0, 0], аналитический и численный | −0.002347, и ещё 20 компонент |
| Доля правильных на отложенной выборке | **0.947** |
| Забыта производная ReLU | 0.887, расходятся 15 из 21 компонент |
| Перепутан знак градиента | 0.500, расходятся все 21 |

Ошибка в производной ReLU не мешает сети обучиться до правдоподобной
точности: внешне это выглядит как неудачные данные. Проверка градиента её
ловит, но не на всех весах: шесть весов второго слоя от производной ReLU не
зависят. Проверка одной компоненты из `W2` вместо `W1[0, 0]` пропустила бы
ошибку.

Чего не делает: не использует мини-пакеты и оптимизаторы сложнее
градиентного спуска; не меняет данные; градиент проверяется на маленькой сети
2–5–1, а не на обучаемой.

## Граф задач и отказы (`dag`)

| Что видно | Значение |
|-----------|----------|
| «Обучение» падает дважды, три попытки (по умолчанию) | 7 из 7, попыток 9 |
| «Обучение» не восстанавливается, две попытки | **4 из 7**, пропущено 2 |
| Ребро «публикация → выгрузка» | граф отвергнут до запуска |

Без ребра «оценка → публикация» конвейер публикует модель, так и не прошедшую
оценку, — журнал это помечает. Такое ребро — не формальность, а единственное,
что стоит между сбоем и выпуском.

Чего не делает: не исполняет задачи одновременно; не ждёт между попытками; не
повторяет Airflow — расписания, таймаутов и состояния между запусками здесь нет.

## Что площадки нашли в материалах

Первая версия площадок повторяла числа лекций, и, повторяя, перепроверила сами
лекции. Найденное исправлено **в материалах**, а не подогнано в площадках:

1. **Лекция 6 сравнивала несимметричные конвейеры:** утечная ветвь без
   `StandardScaler`, честная — с ним. Теперь обе масштабируют. На вывод это не
   влияло, но сравнение должно отличаться только тем, что обсуждается.
2. **Лекция 5 печатала только вырожденный случай Lasso:** при наибольшем штрафе
   обнулены все десять признаков и R² отрицательный — это отказ от модели, а не
   отбор. Добавлены строки для alpha ≈ 10 и пояснение о разной силе штрафа у
   Ridge и Lasso при одной alpha.
3. **Лекция 6 не комментировала, что веса классов снизили полноту.** Добавлено
   пояснение про чистые листья.
4. **Демонстрация переобучения в лекции 4 зависела от версии scikit-learn:**
   на 1.9 степень 17 сглаживалась, и рисунок переставал показывать то, о чём
   говорит текст. Лекция теперь строит многочлен через
   `numpy.polynomial.Polynomial.fit`.
5. **Лекция 2 печатала «в 5 раз» на Python 3.12 и «в 4 раза» на 3.10:**
   отношение памяти равно 4.5, и округление до целого решала версия. Теперь
   печатается одна цифра после запятой.

Пункты 4 и 5 нашла не площадка, а проверка на нескольких версиях Python в CI.
После этого связь площадок с лекциями ослаблена до общей темы: точное
совпадение чисел оказалось хрупким — оно зависело от версий библиотек — и
требовало править лекции ради площадок.

## Как собрать сайт

Сайт собирается целиком, вместе с площадками второго курса, — см. раздел о
развёртывании в [README](../README.md). Площадки ИСТ-51 оказываются в `dist/ml-practice/`,

ошибок видна только там — заглушка `pyarrow`, отсутствующее в Pyodide колесо,
слишком тяжёлая зависимость, 32-битные указатели WebAssembly.

## Как проверить

```bash
ruff check . && pytest
```

Тесты делятся на три группы:

- **свойства** (`test_leak_experiment.py`, `test_metric_metrics.py`,
  `test_fit_models.py`, `test_data_cleaning.py`, `test_nn_network.py`,
  `test_dag_scheduler.py`) — то, что площадка утверждает, проверяется как
  свойство: утечка завышает оценку, честная оценка близка к истине, ошибка на
  обучении падает с гибкостью, а на новых данных — нет. Немногие точные значения
  в них — факты о фиксированных данных: их изменение значит, что изменились
  данные или алгоритм. Числа, зависящие от версии библиотек или платформы,
  точно не закрепляются;
- **видимые строки** (`test_<slug>_app_smoke.py`) — интерфейс рендерится на
  поддельном Streamlit, и проверяется то, что студент действительно увидит, а
  не то, что вернула функция;
- **один элемент управления — одна причина** (`test_<slug>_controls.py`) — ни
  одна ручка не должна менять две вещи сразу. Ползунок, управлявший и
  генерацией данных, и разбиением выборок, — названная ошибка
  репозитория-образца: двигать его было можно, а вывода из опыта не следовало.

Плюс общие инварианты каркаса: реестры `APPS` и `PLAYGROUNDS` обязаны совпадать,
у каждой площадки есть курс и тема,
площадки не должны видеть файлы друг друга, `scikit-learn` объявляется только
там, где он нужен, версия stlite закреплена точно. Данные в `data/` сверяются с
пересчётом скриптом подготовки.

## Как добавить площадку

1. Пакет `<slug>_playground/` из чистых модулей; `app.py` — единственный файл,
   знающий про `streamlit`. Строка боковой панели —
   `other_playgrounds("ml-practice/<slug>")`, путь буквально: это проверяет тест.
2. Запускающий файл в корне на шесть строк.
3. Строка `App(slug="ml-practice/<slug>", ..., template=IST51_TEMPLATE)` в `APPS`
   (`scripts/build_site.py`) и `Page(...)` с темой в `IST51` (`playground_common/links.py`).
4. Тесты всех трёх групп.
5. Раздел в этом файле; название — в `TITLES` файла `площадки.py` при материалах курса.

Правила, которые каркас не проверит за вас:

- идентификаторы, докстроки и комментарии — английские, весь видимый студенту
  текст — русский;
- площадка ссылается на тему, а не на занятие: без «как в лекции N» и без
  цитат, которые разойдутся с материалами при первой их правке;
- `lru_cache`, а не `st.cache_data`: браузер пересчитывает всё на каждый rerun;
- `patch_pyarrow_stub()` до первого импорта `sklearn`;
- то, что не считается в браузере, считается офлайн и кладётся числами в
  `<slug>_playground/data/`, а интерфейс честно выключает недоступное;
- подписи-метки на осях plotly (`#8`, `глубина 3`) — с явным
  `"type": "category"`, иначе plotly разложит их по числовой оси;
- цвета из `playground_common/palette.py` — только для данных; текст и сетку
  задаёт тема, иначе в тёмной теме подписи не читаются.
